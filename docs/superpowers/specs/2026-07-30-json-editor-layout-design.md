# JSON 格式化双栏编辑器设计

## 目标

把现有 JSON 格式化工具改为更大的左右双栏工作区：左侧输入原始字符串，右侧显示并允许编辑结构化 JSON。右侧需要支持语法高亮和对象、数组折叠，方便阅读复杂结构。

## 范围

- 仅调整 `json-format` 工具，不改变其他通用工具的布局和输出组件。
- 保留现有 JSON5、缩进、格式化、压缩、验证、清空和复制能力。
- 不增加左右内容实时同步，也不提供 JSON 树表单或字段级可视化编辑。

## 页面布局

- 桌面端使用左右双栏，左侧约占 44%，右侧约占 56%。
- 两侧编辑区等高，高度采用响应式视口尺寸，并设置最小值和最大值，保证工作区明显大于当前文本框。
- 窄屏端沿用响应式布局，自动切换为上下排列。
- 左侧标题为“输入”，使用普通多行文本框输入原始 JSON 或 JSON5 字符串。
- 右侧标题为“格式化结果”，使用可编辑的 JSON 代码编辑器，并保留复制按钮。

## 右侧编辑器

右侧使用 CodeMirror 6，启用以下能力：

- JSON 语法高亮；
- 行号；
- 括号匹配；
- 折叠边栏和折叠快捷交互；
- 对象与数组默认全部展开；
- 折叠对象或数组后，以包含省略号的占位形式展示，例如 `{…}` 或 `[…]`；
- 内容可直接编辑，并通过 `v-model` 更新右侧结果状态。

编辑器视觉样式使用项目现有 CSS 变量适配背景、边框、文字和主题，不引入与当前页面不一致的独立设计系统。

## 数据流与操作行为

1. 用户在左侧输入原始内容。
2. 用户点击“格式化”或“压缩”后，现有 JSON 工具执行器解析左侧内容并生成结果。
3. 成功结果写入右侧编辑器，并覆盖右侧此前的内容与手工修改。
4. 用户在右侧编辑时，只更新右侧结果，不回写左侧。
5. 用户再次执行操作时，仍以左侧内容为唯一输入。
6. “复制”复制右侧编辑器的当前完整内容，包括用户手工修改后的内容。

“验证”沿用现有语义：验证左侧输入。成功时显示现有成功结果，失败时使用现有错误提示区域展示解析错误。

## 组件边界

- `jsonFormat` 工具配置声明横向布局，并声明使用 JSON 编辑器结果区所需的展示元数据。
- `ToolView` 根据工具元数据选择普通 `OutputBox` 或 JSON 编辑器结果组件，其他工具继续使用原有输出框。
- 新的 JSON 编辑器结果组件负责 CodeMirror 生命周期、右侧编辑同步、折叠、主题样式和复制。
- JSON 解析、格式化和压缩逻辑继续留在现有工具执行器中，不与编辑器组件耦合。

## 错误与边界情况

- 每次执行操作前沿用现有行为清空右侧结果；空输入或解析失败时显示现有错误信息，右侧保持为空。
- CodeMirror 接收到父级新结果时更新文档；自身编辑产生的更新不会形成重复写入循环。
- 路由切换或组件卸载时销毁编辑器实例，避免残留监听器。
- 长 JSON 依靠编辑器滚动，不无限撑高页面。
- 手机端上下排列时，两侧保持足够高度并允许独立滚动。

## 测试与验收

- 工具配置测试：JSON 工具声明横向布局和结构化结果编辑器。
- 页面测试：JSON 页面渲染左侧输入与右侧 JSON 编辑器，且右侧列宽大于左侧。
- 交互测试：格式化结果写入右侧；右侧可编辑且不回写左侧；再次格式化会覆盖右侧手工修改。
- 功能测试：编辑器启用 JSON 语言支持、行号和折叠能力，默认不主动折叠节点。
- 回归测试：现有 JSON 格式化、压缩、验证和 JSON5 测试继续通过，其他工具仍使用普通输出框。
- 运行完整测试、类型检查和生产构建，并在桌面与窄屏视口进行视觉检查。

## 非目标

- 不实现左右实时同步。
- 不实现拖动调整栏宽。
- 不实现字段级树形表单、JSON Schema 校验或自动补全。
- 不改变其他工具的默认布局。
